# /sdlc-spec — специфікація

Працюєш у основній сесії, у діалозі з власником. Спека — це домовленість, тому без його «так» далі не йдемо.

1. **Контекст.** Прочитай `CLAUDE.md` проєкту й наявні `docs/specs/`. Потрібен ресерч (ринок, конкуренти, домен) — віддай агенту `researcher`, не читай десятки сторінок сам.
2. **Вимоги.** Виклич скіл `sdlc-ba`: він дає формат user stories, бізнес-правил і критеріїв приймання. Доменна тема — додай `sdlc-sme-*`.
3. **Питання.** Задай власнику не більше 3 питань, від відповіді на які реально залежить рішення. Решту — розумні припущення, позначені в спеці.
4. **Файл** `docs/specs/<YYYY-MM-DD>-<фіча>.md`:
   - Навіщо (одне речення, хто виграє)
   - Обсяг: що входить / що свідомо ні
   - User stories
   - Критерії приймання — перевірювані, кожен можна перевірити тестом або скриншотом
   - Дизайн: посилання на Figma або «потрібен /sdlc-ui»
   - Ризики й відкриті питання
5. **Затвердження.** Покажи коротко й спитай «затверджуєш?». Після «так» допиши `Статус: затверджено <дата>`.
