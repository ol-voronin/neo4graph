# Компании и госденьги: архитектура

Статус: проект, 19.10.2026. Ветка `companies-graph`.

## Цель

Запрос по ЄДРПОУ или названию компании показывает её карточку и всё, что связывает компанию с государством:
- кто платил ей бюджетные деньги (spending.gov.ua, уже есть);
- какие закупки она выиграла и у каких заказчиков (Prozorro, новое);
- признаки риска: банкротство, санкции (новое);
- суды (уже есть, ЄДРСР).

Центр графа здесь компания, а не человек. Люди появляются только как должностные лица из карточки ЄДР (директор, учредитель), то есть как часть записи о компании. Поиск по ФИО в этот контур не входит.

## Что уже есть и переиспользуется

| Часть | Где | Роль |
|---|---|---|
| Озеро данных | `src/lake.py`, release `lake-latest`, ночью 05:17 Kyiv | ЄДР юрлиц (`uo`), поиск компании по названию и коду |
| Карточки компаний | таблица `edr_orgs` (Neon) | компании, попавшие в граф |
| Госплатежи | `src/spending.py` → `public_payments` | плательщик (госорган) → компания |
| Очередь | `query_queue`, `web/api/queue.js`, workflow `queue.yml` | запрос пользователя → сбор |
| UA-воркер | `local/ua_worker.py` (LaunchAgent на Маке) | только то, что недоступно из облака |
| Граф | `web/api/graph.js`, `web/api/node.js` | узлы и связи, панель доказательств |

## Ограничения, под которые всё строится

1. **Neon free: 0,5 ГБ, занято 293 МБ.** В базу кладём только то, что показывает граф: агрегаты и топ записей. Полные выгрузки хранятся в Parquet в озере (GitHub release), не в Postgres.
2. **API Prozorro (`public.api.openprocurement.org/api/2.5`) не ищет по ЄДРПОУ.** Есть только лента изменений (`/tenders`, `/contracts` с offset) и карточка по внутреннему id. Поле `suppliers` в ленте не отдаётся (`opt_fields` его не включает), нужен отдельный GET на каждый контракт. Поиск сайта `prozorro.gov.ua/api/search/tenders` (POST `text=`) находит по коду, но это неофициальный интерфейс и в ответе нет внутреннего id.
3. **Из облака доступно:** Prozorro CDB, spending.gov.ua, data.gov.ua. UA-IP нужен только ЄДРСР и НАЗК, это остаётся в воркере.

## Схема потоков

```

                     │
                     ▼
        resolve: озеро uo → ЄДРПОУ ──> edr_orgs
                     │
     ┌───────────────┼──────────────────────┬─────────────────────┐
     ▼               ▼                      ▼                     ▼

 (есть)         pz_contracts.parquet   bankrupt, sanctions   суды ЄДРСР (есть)
     │               │                      │                     │
     ▼               ▼                      ▼                     ▼

     └───────────────┴──────────┬───────────┴─────────────────────┘
                                ▼
                    graph.js / node.js (режим «компания»)
```

## Компоненты

### 1. Prozorro: контракты в озере

Новый `src/prozorro.py`, запуск в `lake.yml`.
- **Синхронизация:** лента `/api/2.5/contracts` по offset. Offset хранится в `lake/state/prozorro.json`, каждую ночь берём только изменения с прошлого запуска. Для каждого нового или изменённого контракта делаем GET `/contracts/{id}`, 5–10 параллельных запросов.
- **Таблица `pz_contracts.parquet`:** `contract_id, tender_id, buyer_edrpou, buyer_name, supplier_edrpou, supplier_name, amount, currency, date_signed, status, cpv`.
- **Первичная загрузка истории** идёт отдельным ручным запуском workflow по годам (`--from 2023-01-01`), частями по ~6 ч. Это лимит одного job в Actions.
- **В Neon** только агрегат `public_contracts(buyer_edrpou, supplier_edrpou, n, total, d0, d1, top_contracts jsonb)` для компаний из `edr_orgs`. Те же правила, что у `public_payments`.
- **Быстрый старт до загрузки истории:** для компании из очереди находим тендеры через поиск сайта (`text=<ЄДРПОУ>`), сверяем код точным совпадением, а детали берём из CDB. Этот обходной путь помечен как неофициальный и уходит, когда загрузится история.

### 2. Признаки риска компании

Шаг `src/lake.py build --only flags`. Только записи с 8-значным ЄДРПОУ, физлица отбрасываются при загрузке.
- **Банкротство:** ДСА «Відомості про справи про банкрутство», ежедневно. Мин'юст РБА — разово, архив до 2024.
- **Санкции:** реестр санкций СНБО для юрлиц, «Війна і санкції» НАЗК для компаний.
- **Таблица `company_flags.parquet`:** `edrpou, flag (bankrupt|sanctioned), source, date, case, detail, url`.
- **В Neon:** `company_flags` только для компаний из `edr_orgs`.

### 3. Карточка компании: YouControl

- Сейчас: парсинг публичной страницы (`yc_company` в воркере), остаётся по решению владельца.
- Когда будет ключ: `GET https://api.youscore.com.ua/v1/usr/{ЄДРПОУ}` с `Authorization: Bearer $YOUSCORE_API_KEY`. Дополнительно `/v1/vat`, `/v1/sanctions`, `/v1/secou`, `/v1/licenses` по коду. Ключ лежит только в `.env` воркера и в секретах Actions. Если ключ есть, используется API; если нет, парсинг.
- Методы YouScore по физлицам (`individuals*`, `myrotvorets`, `passports` и т. п.) не используются.

### 4. Граф: режим «компания»

- `graph.js`: новые связи `won_tender` (заказчик → компания, сумма, число контрактов) и `risk_flag` (компания → флаг).
- `node.js`: в карточке компании блоки «госплатежи», «закупки», «риски» и «суды». Каждая цифра со ссылкой на источник.
- Подписи «по данным …» и дата среза. Устаревшие реестры (заморожены с 2022–2024) явно помечаются.

## Риски

- **Объём Prozorro.** Миллионы контрактов за всё время. Поэтому история грузится частями и только в Parquet, а в Neon идут агрегаты.
- **Лимиты API.** Поставить паузы и ретраи, User-Agent проекта, не больше 10 потоков.
- **Неофициальный поиск prozorro.gov.ua** может поменяться. Это временный путь с проверкой кода, не основа системы.
- **Neon.** Перед каждым шагом считать прирост, держать запас ≥ 150 МБ.
