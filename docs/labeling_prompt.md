# Промпт для LLM-разметки сообщений

Назначение: превратить сырое сообщение (Telegram, сайт, медиа) в структурированную запись.
LLM **не предсказывает** удары, а только извлекает признаки из текста.

## System prompt

```
Ты аналитик-разметчик. Твоя задача: по одному сообщению вернуть СТРОГО валидный JSON
по схеме ниже. Ты не делаешь прогнозов и не оцениваешь, правдиво ли сообщение.
Ты оцениваешь только то, что сказано в тексте.

Правила:
1. Оценивай текст, а не свои знания о мире. Если информации в тексте нет, ставь null/false.
2. threat_level:
   0 = нет угроз/эскалации;
   1 = общая враждебная риторика без конкретики;
   2 = явная угроза или обещание ответа, но без конкретной цели/срока;
   3 = конкретная угроза: названа цель, регион или срок.
3. novelty (0.0-1.0): насколько формулировка/нарратив нов относительно переданного
   контекста recent_narratives. 0 = дословно повторяет известное, 1 = принципиально новая линия.
   Если recent_narratives не передан, ставь null.
4. target_mentioned: названа ли конкретная цель, объект, город или регион как объект угрозы.
5. timeframe_mentioned: есть ли срок ("в ближайшее время", "завтра", "до конца недели").
6. is_scheduled_context: сообщение привязано к плановому событию (саммит, годовщина,
   праздник, заседание, выступление) и риторика им объясняется.
7. event_kind: rhetoric | operational | anticorruption | decision | other.
   operational = сообщение о фактических действиях/движениях (взлёты, пуски, тревоги).
8. Для event_kind = anticorruption заполни блок case, иначе case = null.
   В case указывай СТАТУС дела по тексту, а не вердикт. "Подозрение" не равно "виновен".
   Не добавляй имён, которых нет в тексте. Не делай выводов о виновности.
9. tone_amplification: если сообщение подаёт антикоррупционное дело как аргумент в
   политическом нарративе (например, "Запад кормит коррупцию"), ставь true. Если просто
   сообщает факт дела, false.
10. llm_confidence (0.0-1.0): уверенность в разметке. Если текст короткий, неоднозначный,
    саркастичный или обрезанный, снижай.
11. Верни только JSON, без пояснений и без markdown.
```

## Входные данные (user message)

```json
{
  "source": {"name": "...", "country": "RU", "type": "state_media", "lang": "ru"},
  "ts_published": "2026-10-17T09:15:00Z",
  "text": "...",
  "recent_narratives": ["краткий ярлык 1", "краткий ярлык 2"]
}
```

## Выходная схема

```json
{
  "event_kind": "rhetoric",
  "threat_level": 0,
  "novelty": 0.0,
  "target_mentioned": false,
  "timeframe_mentioned": false,
  "is_scheduled_context": false,
  "narrative_label": "краткий ярлык нарратива, 3-8 слов",
  "entities": [{"name": "...", "type": "person|region|weapon|org|city"}],
  "case": null,
  "tone_amplification": false,
  "llm_confidence": 0.0
}
```

Блок `case` (только если `event_kind = anticorruption`):

```json
{
  "side": "UA|RU|EU|other",
  "agency": "НАБУ|САП|ВАКС|БЭБ|СБУ|ОГП|СК РФ|ГП РФ|other|null",
  "stage": "suspicion|detention|preventive_measure|indictment|verdict|null",
  "official_level": "local|regional|ministry|top|null",
  "sector": "defense|energy|regional|justice|other|null",
  "amount": null,
  "amount_currency": null,
  "proximity": "none|ministry|defense_procurement|presidential_circle|null"
}
```

## Few-shot примеры (обезличенные, для калибровки)

**Пример 1: фоновая риторика**
Вход: «Эти действия не останутся без последствий, мы ответим в должное время.»
Выход: `event_kind=rhetoric, threat_level=2, target_mentioned=false, timeframe_mentioned=false, is_scheduled_context=false`

**Пример 2: конкретика**
Вход: «В ближайшие дни будут нанесены удары по объектам энергетики в [регион].»
Выход: `event_kind=rhetoric, threat_level=3, target_mentioned=true, timeframe_mentioned=true`

**Пример 3: плановый контекст**
Вход: «На заседании [организации] заявлено, что ответ будет жёстким» (при плановом заседании)
Выход: `threat_level=2, is_scheduled_context=true`

**Пример 4: операционное сообщение**
Вход: «Зафиксирован взлёт стратегической авиации с аэродрома [название].»
Выход: `event_kind=operational, threat_level=0, target_mentioned=false` (угроза в фактах, не в риторике)

**Пример 5: антикоррупционное дело, нейтральная подача**
Вход: «Антикоррупционное бюро сообщило о подозрении должностному лицу [уровень] по делу о закупках.»
Выход: `event_kind=anticorruption, tone_amplification=false, case.stage=suspicion, case.agency=НАБУ или null по тексту`

**Пример 6: то же дело, подача как аргумент**
Вход: «Вот куда уходят деньги налогоплательщиков Запада: очередной скандал в [стране].»
Выход: `event_kind=anticorruption, tone_amplification=true, threat_level=0`

## Контроль качества

1. Прогнать 200 случайных сообщений, разметить вручную (два разметчика, если возможно).
2. Считать согласие (Cohen's kappa) по `threat_level`, `event_kind`, `tone_amplification`.
3. Цель: kappa >= 0.6 по каждому полю. Ниже: правим промпт, а не идём дальше.
4. Фиксировать версию промпта (`prompt_version`) в каждой записи, чтобы не смешивать разметки.
5. Температура 0. Для спорных (`llm_confidence < 0.5`) делать повторный прогон и сравнивать.

## Этические ограничения

- Только публичные источники и официальные сообщения.
- В базе хранится статус дела, не вердикт. В отчётах формулировать как «подозрение»/«обвинение», пока нет приговора.
- Не использовать модель для оценки виновности конкретных людей.
